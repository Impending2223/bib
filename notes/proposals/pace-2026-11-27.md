# Running more agents at once, and where tokens go

Nov. 27, 2026, about 8:50 p.m. PT. For the owner, in answer to "Could we assign more agents? ... Their tasks don't conflict, do they? ... Is there anything we're doing that's wasteful of tokens?"

## What can run at once

Two agents conflict only when both change the same entry. The leftovers are cut by month, so no two month batches touch the same entry. Ruling 63 already allows batches like these to run at the same time; only the readers within one batch must go one after another.

I had been running the audits one at a time, which the ruling does not require. That was slower than it needed to be.

From tonight the leftovers run side by side:

- Running now: the audit of July to October 1966, and five readers: November 1966 to May 1967, June 1967 to February 1968, March to June 1968, July 1968 to January 1970, and the stragglers (22 points from earlier months, added after their months ran).
- Each audit starts as soon as its reader reports, alongside the others.
- The merges still go one at a time, under the lock. A merge takes a few minutes.

The machine carries about six heavy agents at once while a merge runs. That is the limit now, so more agents would not go faster tonight.

## What should not run beside them

- The nations' new codes (ruling 67). The rename touches the tags of thousands of entries, so it should run when no patch is waiting.
- The notes pass. Its batches take entries by rank, from every year, so they would touch the same entries as the leftovers. It starts when the leftovers are done. Its own batches hold different entries, so three or four of them can then run at once.
- The review of how the China entries are sorted into threads (R27) changes only the `thread:` and `also:` fields, which the leftovers rarely touch. It can run beside the notes pass.

## Where tokens go

- An Opus audit costs about as much as its Sonnet reader, or a little more: about 480,000 to 640,000 tokens, against about 400,000 for the reader. That is the order you set: Sonnet reads first, Opus audits. The audits earn their cost: the last one corrected 60 of the reader's 91 changes.
- The patch check reloads the whole calendar each time and takes two to four minutes. Agents run it many times, and some lost runs to the time limit and ran it again. A faster patch check that loads only the entries a patch touches would save time and tokens in every reader and every audit. I will write it after the leftovers, unless you would rather keep the code as it is.
- Some agents kept running after their reports and repeated them. The guide now tells them to stop every watch before they report.
- Little else is spent for nothing. Each agent reads its own pages, and the briefs point to the guide rather than repeating it.
